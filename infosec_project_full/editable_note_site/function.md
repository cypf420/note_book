# YCY 本地笔记工作台功能基线

本文件是后续修改 `index.html`、`style.css`、`app.js`、`scripts/server.py` 时必须遵守的功能基线与交互约束。后续重构应优先对齐本文件，而不是只对齐某一次临时界面效果。

## 1. 项目定位

这个项目是一个“本地优先的 Markdown 笔记工作台”，不是纯前端展示页。

核心定位：

- 读取站点内已有 Markdown 文档。
- 将网页正文导入并转换为 Markdown。
- 下载网页图片并落到本地资源目录。
- 在浏览器内完成阅读、检索、编辑、导出、分组和同步。
- 使用 `content/library.json` 维护文档索引、文件夹结构和顺序。

当前界面定位：

- 前端采用 VS Code 风格的工作台布局。
- 左侧为 Activity Bar + Explorer / Search / Sync / Settings 侧栏。
- 中间为默认所见即所得编辑区。
- 右侧为 TOC / 大纲侧栏。
- Markdown 源码视图是附加面板，不是默认主界面。

## 2. 当前必须保留的功能

### 2.1 文档读取与渲染

- 能读取 `content/library.json` 中登记的文档。
- 能打开主文档和导入文档。
- 文档正文以 Markdown 为源，渲染为可读页面。
- 页面支持目录锚点、标题跳转、哈希路由。
- 当前文档路径、slug、标题、来源等信息可见。

对应要求：

- 不能把渲染逻辑改成只认 HTML 存储。
- 不能让阅读区脱离 Markdown 数据源单独维护。

### 2.2 本地保存与落盘

- 支持新建空白文档。
- 支持编辑现有文档。
- 支持保存到站点。
- 保存时自动更新 `content/library.json`。
- 导入文档默认落到 `content/imports/<slug>.md`。
- 未保存的编辑内容允许保存在浏览器 `localStorage`。

对应要求：

- 后续改编辑器时，保存动作仍必须回到 Markdown 文本。
- 不能只保存浏览器状态，必须能真正写回本地文件。

### 2.3 网页导入

- 支持输入 URL 后抓取网页正文。
- 支持识别 `html / markdown / text`。
- 支持把网页内容转换为 Markdown。
- 支持导入到编辑区但不立即落盘。
- 支持导入并直接保存到站点。
- 导入网页图片时，资源落到 `content/assets/<slug>/`。

对应要求：

- 导入结果必须可继续编辑和保存。
- 导入到编辑区后，默认直接进入所见即所得编辑状态。
- 不能把导入功能改成只有预览、没有落盘链路。

### 2.4 文档删除与资源清理

- 支持删除已保存的导入文档。
- 删除时同步更新 `content/library.json`。
- 删除时同步清理 `content/assets/<slug>/` 资源目录。
- 未保存的临时导入内容不能直接删除为已落盘文档。

### 2.5 文件树与文件夹管理

当前文件树基线：

- 文件树表现层采用接近 VS Code Explorer 的视觉与交互。
- Explorer 根层不显示站点壳目录 `editable_note_site`。
- Explorer 根层直接展示工作内容。
- `新手引导` 作为第一个顶层文件夹保留。
- 文件与文件夹按树结构显示，支持展开、折叠、选中、高亮当前文档。
- “分组”在前端交互上统一表现为“文件夹”。
- 文件夹树仍然优先复用当前索引模型，不直接暴露本机真实磁盘目录。
- 当前文档切换后，文件树高亮必须同步。

必须保留的树能力：

- 支持未分组状态。
- 支持树形文件夹和子文件夹。
- 支持文件夹筛选。
- 支持文件夹折叠/展开。
- 支持新建文件夹、重命名文件夹、调整父级层级、删除空文件夹。
- 支持文档在组内上移/下移。
- 支持拖拽文档到不同文件夹或不同位置。
- 文件和文件夹都支持 Explorer 右键上下文菜单。
- 文件夹右键菜单至少包含：新建空白文件、新建空白文件夹、获取网页内容、重命名、删除。
- 文件右键菜单至少包含：打开、重命名、删除、复制路径。

对应要求：

- 后续 UI 可以重做，但树结构能力不能丢。
- 文件夹信息仍需通过 `library.json` 的 `groups / group / order` 表达。
- 如果要支持更多“空文件夹”场景，必须兼容现有文档数据，不得破坏已有内容。

### 2.6 Explorer 加号菜单

Explorer 标题栏右侧的新增入口是正式功能，不是装饰。

点击后必须提供且仅提供以下三项动作：

1. 获取网页内容
2. 新建空白文件
3. 新建空白文件夹

对应要求：

- “获取网页内容”必须接到现有网页导入逻辑。
- “新建空白文件”必须接到现有新建文档逻辑。
- “新建空白文件夹”必须真正写入文件夹结构，不允许只做 UI 占位。
- 入口位置和交互应保持接近 VS Code Explorer 的标题栏新增按钮区域。

### 2.7 搜索与导航

- 支持全文搜索标题和正文。
- 搜索索引在浏览器端渐进构建。
- 搜索结果可直接打开对应文档。
- 支持左侧资源管理器导航。
- 支持右侧 TOC / 大纲导航。
- 支持 `#doc=<slug>&section=<heading-id>` 的定位方式。
- TOC 标题文本必须经过清洗，不能把锚点符号、富文本残留符号、段落标记、异常空白直接带入目录。
- TOC 必须适配中英文混排、长标题换行和窄侧栏显示，不能出现文字重叠或乱码式堆叠。

对应要求：

- 后续改动不能把搜索退化成仅搜索标题。
- 不能破坏通过 URL 直接定位文档和章节的能力。

### 2.8 Activity Bar 与侧栏交互

当前左侧主导航基线：

- 主功能入口统一收敛到 VS Code 风格 Activity Bar。
- 图标默认只显示图形，不显示名称。
- 鼠标悬停后约 1 秒再显示提示名称。
- 图标必须有 active、hover 和浅色 / 深色两套视觉状态。

当前至少应覆盖这些侧栏能力：

- 资源管理器 / 文件树
- 搜索
- 导入 / 同步
- Markdown 源码入口
- 设置 / 维护
- 主题切换

对应要求：

- 不再允许恢复为顶部大块中文按钮阵列作为主入口。
- 高频功能必须能通过图标或对应侧栏面板找到。
- 主题切换属于 Activity Bar 图标入口的一部分，不应回退到顶部大按钮。

### 2.9 阅读与界面控制

- 支持阅读宽度切换。
- 支持浅色 / 深色主题切换。
- 支持专注模式。
- 支持左侧栏、右侧栏开合。

明确的交互要求：

- 顶部不再允许保留大面积功能按钮区。
- 正文区域应优先保证阅读空间。
- 侧栏和工具栏的存在不能长期压缩正文可读区域。

### 2.10 编辑模式与所见即所得

当前编辑模式基线：

- 默认进入所见即所得模式。
- 打开文档时优先看到可直接编辑的正文。
- 从网页导入的新内容默认直接进入所见即所得。
- Markdown 源码视图是附加功能，需要通过显式入口打开。
- 打开源码视图时，不应破坏当前所见即所得状态。
- 所见即所得工具栏不再提供“行内代码”按钮。

保存原则：

- Markdown 仍然是保存和落盘的真实来源。
- 所见即所得只是交互层，不得绕过 Markdown 存储。
- 支持常见 Markdown 快捷语法转换。
- 支持标题、列表、引用、代码、链接等基础编辑。

后续导向：

- 所见即所得继续向 Typora 体验逼近。
- 但实现方式必须是“编辑体验升级”，不是“丢掉 Markdown 改存 HTML”。
- 若替换为更完整的编辑器内核，仍需保证 Markdown round-trip 稳定。

### 2.11 导出与共享同步

- 支持导出 Markdown。
- 支持上传共享笔记。
- 支持扫描共享分支列表。
- 支持从共享分支导入到本地。
- 共享社区采用“每个贡献者一个共享分支”的结构。
- 共享分支命名应包含作者信息，不再只按学院 / 专业 / 年级命名。
- 每个共享分支必须写入 `shared_notes/manifest.json`。
- `manifest.json` 至少要描述作者、学院、专业、年级、发布时间、文档数、分组数、标签、摘要和文档预览。
- 中央共享索引固定为 `shared_notes/shared-index.json`。
- 共享列表前端必须优先读取中央 `shared-index.json`，仅在索引缺失或损坏时回退到远程分支扫描。
- 中央 `shared-index.json` 由 GitHub Actions 汇总共享分支中的 `manifest.json` 自动生成。
- 上传共享笔记应采用后台任务式交互。
- 点击开始上传后，用户可以关闭上传弹窗并继续编辑。
- 页面下方或右下角必须持续显示上传状态，至少包含：正在上传、上传成功、上传失败。
- 上传失败后应尽量提供重试入口。
- 导入共享笔记后，内容仍然必须写回本地工作区和 `content/library.json`，不能变成只读远程引用。

对应要求：

- 共享同步属于正式功能，不是临时调试入口。
- 后续改 UI 时不能把这条链路删掉或藏到不可用位置。
- 上传职责是生成 / 更新贡献者分支与 `manifest.json`；中央索引汇总职责交给 GitHub Actions。
- 拉取职责是先读中央索引决定候选项，再按需导入具体贡献者分支。

### 2.12 运行模式

必须继续区分两种运行方式：

- 静态模式：能阅读、搜索、导航，但不能执行需要本地服务的写操作。
- 本地服务模式：能保存、导入网址、删除、同步、关闭站点。

对应要求：

- 前端必须继续识别当前是否运行在 `127.0.0.1 / localhost`。
- 需要服务端的功能在静态模式下必须明确禁用，而不是静默失败。
- “退出站点”属于设置与维护侧栏中的正式能力，不得丢失。
- 本地服务模式下，退出站点必须通过前端入口触发 `/api/shutdown`。
- 静态模式下，退出站点按钮必须禁用，并明确提示当前无法关闭本地服务。

## 3. 数据与目录约束

后续改代码时，以下目录语义不得擅自更改：

- `content/library.json`
  文档索引、文件夹、顺序的真实来源。
- `content/imports/`
  导入后的 Markdown 文档目录。
- `content/assets/<slug>/`
  网页导入时抓下来的图片资源目录。
- `shared_notes/manifest.json`
  每个贡献者共享分支中的元数据文件。
- `shared_notes/shared-index.json`
  默认分支中的中央共享索引文件，由 GitHub Actions 生成。
- `editable-note-site-cache:*`
  浏览器本地临时缓存前缀。

如果确实要变更这些结构，必须同时满足：

- 提供迁移方案。
- 不破坏现有文档。
- 不破坏已有 API。
- 不破坏前端读取逻辑。

否则不允许改。

## 4. 后续改代码的原则

### 4.1 非回退原则

后续任何重构都不得导致以下功能退化：

- 不能失去本地落盘能力。
- 不能失去网址导入能力。
- 不能失去全文搜索能力。
- 不能失去文件树、文件夹管理和拖拽整理能力。
- 不能失去 Markdown 导出能力。
- 不能失去共享上传 / 拉取能力。

### 4.2 Markdown 第一原则

- Markdown 是唯一真实内容格式。
- HTML 渲染是展示层。
- 所见即所得是交互层。
- `library.json` 是索引层。

这四层职责不能混淆。

### 4.3 本地优先原则

- 本地文档必须优先可读、可改、可保存。
- 网络能力是增强项，不是唯一依赖。
- 即使远端同步失败，本地工作流也必须可继续进行。

### 4.4 渐进增强原则

- 能不破坏现有 API 时，不改 API。
- 能在现有数据结构上兼容时，不推翻数据结构。
- 能分阶段替换编辑器时，不做一次性高风险推倒重来。

### 4.5 VS Code 风格约束

- 整体视觉应保持接近 VS Code 的桌面 IDE 风格，而不是回退为网页卡片系统。
- Activity Bar、Explorer、树节点、悬停、选中态、上下文菜单、输入框和源码面板要保持统一视觉语言。
- 浅色 / 深色模式必须覆盖活动栏、资源管理器、编辑区、搜索区、弹出菜单、源码视图和状态提示。

## 5. 未来修改的优先方向

- 继续提升所见即所得，使其更接近 Typora。
- 优化块级编辑体验，例如标题、列表、引用、代码块的原位编辑。
- 提高 Markdown 与所见即所得之间的双向转换稳定性。
- 进一步增强 Explorer 的文件树与上下文操作体验。
- 提高大文档下的搜索、渲染和编辑稳定性。

## 6. 改动验收清单

以后每次改动，至少要检查以下问题：

- 文档还能否正常打开。
- Markdown 是否还能正常保存回文件。
- `library.json` 是否仍正确更新。
- 导入网址后是否还能继续保存。
- 删除文档时资源目录是否还能清理。
- 搜索是否还能搜正文。
- 文件树、拖拽、层级调整是否仍可用。
- Explorer 加号菜单三项动作是否仍都能实际工作。
- 默认是否仍然是所见即所得。
- 源码视图是否仍然是附加入口而非默认主界面。
- 共享上传 / 拉取是否仍可用。
- 共享分支是否仍写入 `manifest.json`。
- 中央 `shared-index.json` 是否仍能驱动共享列表。
- 设置与维护中的退出站点是否仍可用。
- 静态模式和本地服务模式的边界是否仍清晰。
- 顶部是否仍保持无大面积功能按钮区。

## 7. 本文件的使用方式

从现在开始，`function.md` 视为本项目的功能基线文件。

后续任何代码修改都应满足：

- 优先对齐本文件，而不是只对齐某一次临时界面效果。
- 如果某次改动会破坏本文件中的条目，需要先明确说明，再决定是否执行。
- 如果 README、WORKLOG 与本文件冲突，以本文件作为“功能与行为约束”的优先参考。
